OAuth 로그인

카카오 또는 네이버로 로그인해 JWT 토큰을 발급받습니다.

소셜 로그인

내 프로필

로그인된 유저의 프로필 조회 및 수정 API입니다. 모든 요청에 JWT 토큰이 필요합니다.

GET/api/v1/users/me

현재 로그인된 유저의 전체 프로필을 반환합니다. 닉네임, 이메일, 프로필 이미지, 연동 소셜 계정, 즐겨찾는 가수/차단 가수 목록이 포함됩니다.

PATCH/api/v1/users/me/profile

프로필을 수정합니다. 변경할 필드만 입력하면 됩니다 (나머지는 유지). 이미지는 multipart/form-data로 전송됩니다.

차단 관리

특정 가수 또는 곡을 차단하면 추천 결과에서 제외됩니다.

GETPOSTDELETE 차단 가수 관리

차단된 가수는 추천/랜덤 조회에서 제외됩니다. singer_id는 가수 검색 탭에서 확인할 수 있습니다.

GETPOSTDELETE 차단 곡 관리

차단된 곡은 추천 결과에서 제외됩니다. song_id는 내부 DB의 UUID입니다 (Spotify URI 아님).

가수 검색

내부 DB에 등록된 가수를 검색합니다. 온보딩 및 추천 시스템에서 사용하는 데이터입니다.

GET/api/v1/singers/search

가수 이름 또는 별칭으로 부분 검색합니다. 반환되는 singer_id를 차단/즐겨찾기에 사용합니다.

GET/api/v1/singers/random

성별 필터 없이 호출하면 남자 6명 + 여자 6명 기본 반환. gender=male 또는 gender=female 지정 시 해당 성별만 반환. 차단된 가수는 자동 제외됩니다.

곡 검색

Spotify API로 곡을 검색합니다. 검색 결과에서 [찜] 또는 [기록] 버튼으로 라이브러리에 바로 추가할 수 있습니다.

GET/api/v1/music/search

Spotify에서 곡을 검색합니다. 반환 데이터: { name, artist, album_image, uri }. 이 song_data를 그대로 찜/가창기록에 저장합니다. 내부 song DB와는 별개입니다.

버스킹 방 목록 / 생성

온라인 버스킹 라이브 세션을 관리합니다. 방 생성 → 라이브 시작 → 진행 → 종료 순서입니다.

GET/api/v1/busking/rooms

현재 생성된 버스킹 방 목록을 반환합니다. 상태: PREPARING (라이브 전) / LIVE (진행 중) / ENDED (종료)

조회 버튼을 누르세요.

POST/api/v1/busking/rooms — 방 생성

버스킹 방을 생성합니다. 생성 직후 상태는 PREPARING이며, 방 제어 탭에서 라이브 시작을 눌러야 LiveKit 세션이 열립니다. 셋리스트는 곡 검색 탭에서 검색 후 입력하세요.
0 / 3~5곡

방 제어

방 목록에서 복사한 Room ID를 아래에 입력하면 모든 제어 API를 테스트할 수 있습니다.

GET/api/v1/busking/rooms/{id}

방 상세 정보 조회. 셋리스트, 현재 곡 인덱스, 참여자 수, 상태를 반환합니다.

POST/api/v1/busking/rooms/{id}/start

라이브를 시작합니다. LiveKit Room이 생성되고 호스트 토큰이 반환됩니다. 상태가 LIVE로 변경됩니다. 방 생성자만 가능합니다.

POST/api/v1/busking/rooms/{id}/join

뷰어용 LiveKit 토큰을 발급합니다. 이 토큰으로 LiveKit SDK에 연결하면 오디오를 수신할 수 있습니다 (publish 권한 없음).

PATCH/api/v1/busking/rooms/{id}/next-song

셋리스트의 다음 곡으로 넘어갑니다. WebSocket으로 연결된 모든 뷰어에게 SONG_CHANGED 이벤트가 전송됩니다. 호스트 전용.

POST/api/v1/busking/rooms/{id}/end

라이브를 종료합니다. LiveKit Room이 삭제되고 상태가 ENDED로 변경됩니다. 종료 후 결과(reaction 집계) 조회가 가능합니다.

GET/api/v1/busking/rooms/{id}/result

라이브 종료 후 결과를 조회합니다. 곡별 match/mismatch 리액션 수, 총 채팅 수 등이 포함됩니다.

온보딩

POST/api/v1/users/me/onboarding/step1 — 닉네임·사진 설정

신규 유저 닉네임과 프로필 사진을 설정합니다. multipart/form-data로 전송됩니다.
• nickname *필수 — 1~20자 문자열
• profile_image — JPEG / PNG / WebP 이미지 파일 (선택)
JPEG · PNG · WebP 지원 / 없으면 비워두세요

POST/api/v1/users/me/onboarding/step2 — 즐겨부르는 가수 선택

유저가 좋아하는 가수를 선택해 프로필에 저장합니다. 추천 시스템의 초기 선호 데이터로 활용됩니다.
• singer_ids *필수 — 가수 조회 탭에서 확인한 정수 ID 목록 (쉼표로 구분)
가수 탭에서 ID를 먼저 확인하세요

폴더

GET/api/v1/library/folders — 내 폴더 목록

로그인된 유저의 모든 보관함 폴더를 반환합니다. 별도 파라미터 없음.

POST/api/v1/library/folders — 폴더 생성

새 폴더를 생성합니다.
• name *필수 — 폴더 이름 문자열

DELETE/api/v1/library/folders/{id} — 폴더 삭제

폴더를 삭제합니다. 폴더 안의 찜 항목은 함께 삭제되므로 주의하세요.
• id *필수 — 위 목록 조회에서 확인한 폴더 UUID
GET 폴더 목록에서 id 값을 복사하세요

찜 (Wishlist)

GET/api/v1/library/wishlist — 찜 목록 조회

유저의 찜 목록을 반환합니다.
• folder_id — UUID 입력 시 해당 폴더 항목만 필터링 (비워두면 전체 조회)

POST/api/v1/library/wishlist — 찜 추가

곡을 찜 목록에 추가합니다. 곡 검색 탭의 [찜] 버튼을 이용하거나 아래에 직접 입력하세요.
• song_data *필수 — Spotify 곡 정보 JSON: name, artist, album_image, uri
• folder_id — 특정 폴더에 넣으려면 폴더 UUID 입력 (선택)

DELETE/api/v1/library/wishlist/{item_id} — 찜 해제

찜 항목을 삭제합니다.
• item_id *필수 — GET 찜 목록에서 확인한 항목 UUID
GET 찜 목록 응답의 id 값을 복사하세요

가창 기록

GET/api/v1/library/history — 가창 기록 목록

유저의 가창 기록 목록을 반환합니다. 최신순으로 정렬됩니다.
• tag — AGAIN / COMFORTABLE / PRACTICE 등 태그로 필터링 (선택)
비워두면 전체 기록 조회

POST/api/v1/library/history — 가창 기록 저장

곡을 가창 기록에 저장합니다. 곡 검색 탭의 [기록] 버튼을 사용하거나 아래에 직접 입력하세요.
• song_data *필수 — Spotify 곡 정보 JSON: name, artist, album_image, uri
• tags — 가창 태그 목록 (쉼표 구분, ex: AGAIN,COMFORTABLE), 선택
• memo — 자유 메모 (선택)
사용 가능한 태그: AGAIN · COMFORTABLE · PRACTICE · CHALLENGE

PATCH/api/v1/library/history/{id} — 가창 기록 수정

기존 가창 기록의 태그 또는 메모를 수정합니다. 변경하고 싶은 필드만 입력하면 됩니다 (부분 업데이트).
• id *필수 — 수정할 기록의 UUID
• tags / memo — 변경할 값 (선택)
GET 기록 목록 응답의 id 값

DELETE/api/v1/library/history/{id} — 가창 기록 삭제

가창 기록을 삭제합니다.
• id *필수 — GET 기록 목록에서 확인한 UUID
GET 기록 목록 응답의 id 값을 복사하세요

보컬 분석 파이프라인

녹음 파일을 S3에 업로드하고 AI 워커가 보컬을 분석합니다. 분석 완료 후 추천 파이프라인에서 프로필을 사용합니다.

POST/api/v1/analysis/upload-url  [1단계] S3 presigned PUT URL 발급

오디오 파일을 선택하면 presigned URL 발급 → S3 업로드 → s3_key 자동 입력까지 한 번에 처리합니다.

PUTS3 직접 업로드  [1.5단계] presigned URL로 파일 올리기

위에서 URL 발급 후 자동 입력됩니다. 직접 붙여넣기도 가능합니다.

POST/api/v1/analysis/jobs  [2단계] 분석 Job 생성 + SQS 전송

S3 업로드 완료 후 호출. DB에 analysis_job을 생성하고 vocal SQS 큐에 { job_id, s3_key }를 전송합니다. AI 워커가 메시지를 받아 분석을 시작합니다.

GET/api/v1/analysis/jobs/{job_id}  [3단계] 분석 상태 폴링

status: QUEUED → ANALYZING → DONE / FAILED. DONE이면 result_data에 분석 결과가 채워집니다.

GET/api/v1/analysis/profile  보컬 프로필 조회

AI 워커가 분석 완료 후 채워넣는 user_vocal_profiles 테이블 데이터. 추천 1차에서 이 프로필을 사용합니다.

추천 파이프라인

보컬 분석 완료 후 진행. 1차 추천(DB 프로필 기반) → 피드백 → 2차 추천(장르/키워드 필터) 순서입니다.

POST/api/v1/recommendations  [1단계] 추천 Job 생성 + SQS 전송

recommendation_logs에 Job을 생성하고 SQS에 { job_id, user_id }를 전송합니다. 워커가 user_vocal_profiles에서 프로필을 읽어 1차 추천을 수행합니다. (s3_key는 FORCE_PIPELINE 폴백 시에만 필요)

GET/api/v1/recommendations/{job_id}  [2단계] 1차 추천 결과 폴링

status: QUEUED → RUNNING_STAGE1 → WAITING_FEEDBACK. WAITING_FEEDBACK이 되면 first_recommended_songs에 1차 추천 결과(3곡)가 채워집니다.

POST/api/v1/recommendations/{job_id}/feedback  [3단계] 2차 추천 피드백 전송

1차 추천 결과에서 유저가 선택한 곡 IDs를 전송합니다. 워커가 이 데이터를 읽어 2차 추천을 수행합니다. WAITING_FEEDBACK 상태일 때만 가능합니다.

GET/api/v1/recommendations/{job_id}/songs  [4단계] 최종 추천 결과 조회

status가 DONE이 되면 recommended_songs에 2차 추천 결과(장르별 최대 4곡)가 채워집니다.

아티스트 액션

아티스트 선호/차단 정보. 2차 추천 워커가 이 데이터를 참고해 결과를 필터링합니다.

GET/api/v1/artist-actions  내 액션 목록 조회

POST/api/v1/artist-actions  PREFER / BLOCK 설정

같은 아티스트에 이미 액션이 있으면 덮어씁니다 (upsert).

DELETE/api/v1/artist-actions/{artist_name}  액션 취소
